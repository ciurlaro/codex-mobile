# Security review

## Trust model

Codex and every JSON-RPC/tool payload are untrusted requests. Android permissions, current SAF grants, core policy, a one-use UI approval, and the observed storage result decide what happened. The supported runtime and CPU architecture are the pinned ARM64 Codex app-server and stock Android. Device writes are limited to transactional UTF-8 files in app-private storage, explicitly approved exports through `DocumentsProvider`, and the legacy disposable-document rename.

Protected assets are ChatGPT credentials, prompts and responses, user document content, persisted SAF authority, mutation recovery state, and the release/signing chain. The attacker model includes malicious prompt/provider output, malformed or oversized protocol frames, hostile document providers, unsolicited Android IPC, process death, local log/backup extraction, and a changed build dependency.

## Boundary review

| Boundary | Threat | Enforced control | Evidence |
|---|---|---|---|
| Provider input | Prompt injection asks for shell, paths, network, or an unapproved mutation | Session starts read-only with shell, code, MCP, apps, plugins, hooks, and multi-agent features disabled. The built-in read-only Web Search tool is available only for turns carrying Codex Mobile's structured Web Search tag. Android registers only bounded document/workspace tools; core denies unknown tools and requires exact one-use approval for every mutation. | `Step01ProtocolContractTest`, `Step02DynamicToolBridgeTest`, platform device suites |
| JSON-RPC | Invalid UTF-8/JSON, response spoofing, stale session/turn requests, queue or memory exhaustion | Strict UTF-8/JSONL, 4 MiB frame/write limits, 64-event buffer, request timeouts and ID correlation. Server calls require an opened session and active turn; unknown methods receive `-32601`; invalid tools receive `-32602`. Stale-process messages fail the client. | Protocol contract and deterministic fuzz tests |
| Authentication/browser | Code leakage, arbitrary URL launch, login races | Codes live only in bounded UI state and have a redacted `toString`; production logs are absent. Login start/cancel is serialized. Browser handoff accepts only HTTPS on OpenAI/ChatGPT hosts, with no user info or non-443 port. Sign-out uses official `account/logout`. | Agent privacy/protocol tests and Step 06 URL test |
| SAF/document parsing | Guessed paths, escaped IDs, stale grants, provider lies, parser bombs, or MIME spoofing | Source and export trees have separate grants. Random scope IDs and HMAC-authenticated child IDs/cursors replace paths. Reads dispatch from bounded content signatures, not MIME: UTF-8/CSV, PDF, images, DOCX, PPTX, and XLSX. Source size, PDF pages, ZIP entries/expansion, text chunks, image dimensions, metadata, ancestry, and provider observations are bounded and rechecked. XML external entities and Office macros are rejected. | Platform authority, reader fixtures, provider-fault, and fuzz suites |
| Mutation | Implicit/replayed write, partial private changeset, stale overwrite, or false exactly-once claim | Private create/replace changesets use one SQLite transaction with expected hashes and a consolidated full-file diff. Export is a separate approved provider boundary and rejects changed sources/destinations. The UI shows exact source, destination, scope, conflict policy, and diff. Approval is consumable once. Durable recovery records reconcile storage state without re-execution. | `WorkspaceAuthorityTest`, Steps 03–04 suites, journal inspection |
| Android IPC | External component starts work or gains authority | Only the launcher Activity is exported. The foreground service and AndroidX provider are non-exported. A random, one-use private authorization gates foreground starts; notification intents are immutable. There is no boot receiver, scheduler, custom authority, or accessibility service. | Manifest/release inspection and Step 05 lifecycle suite |
| Network | Cleartext or arbitrary destination | Manifest and network-security configuration deny framework cleartext. The native runtime's sole cleartext hop is an authenticated per-process loopback CONNECT control channel; the proxy permits TLS port 443 only for OpenAI/ChatGPT domains, and upstream content remains inside that TLS tunnel. Android system roots supply trust. | Release inspection and loopback proxy tests |
| Logs/crashes | Credentials, codes, prompts, or documents escape | Production code has no logging calls or crash SDK. Runtime stderr is drained and discarded. A private SQLite trigger rejects upstream diagnostic rows and existing rows are securely removed. Notifications are generic/private. Visible failures expose a stable diagnostic category without requiring content logs. | Privacy tests, source/APK/log scans, operations drills |
| Backup/deletion | Private state survives backup or user erasure | Backup is disabled and both backup-rule formats exclude every domain. `account/logout` removes credentials. Android's native clear-data operation erases private/internal-external data, permissions, notifications, and URI grants; it never deletes provider documents. | Manifest inspection and two-phase stock-device deletion test |
| Supply chain | Runtime, wrapper, plugin, or library substitution | Codex version/archive/binary hashes are fixed and verified before packaging; license/notice ship in the APK. Gradle 9.4.1 distribution and wrapper hashes are pinned. Resolved dependencies, including bundled ML Kit OCR, are locked and SHA-256 verified. CycloneDX SBOM is regenerated from release lock state. CI actions are commit-pinned. The transitive ML Kit network-state permission is removed. Release requires an external signing key and R8/resource shrinking. | Preparation script, lock/verification files, SBOM, signed reproducibility gate |

## Residual risk and conclusion

The app necessarily sends prompts and tool results—which can include extracted text, OCR, rendered PDF pages, and images—to OpenAI, trusts Android's system CA and document-provider implementation, and executes a large upstream native runtime. Original files are not passed as arbitrary native tool inputs. Google documents that bundled ML Kit keeps input images/OCR output on-device but sends SDK diagnostics and usage metrics to Google; there is no documented SDK opt-out, so this is disclosed rather than misrepresented. External provider export cannot be made transactional by the app, so interrupted or transformed writes can remain visibly `Unknown`; the private workspace remains authoritative. A production signing key and distribution-account controls remain release-operator responsibilities. Arbitrary filesystem access, general shell, accessibility automation, and runtime updating remain excluded.
